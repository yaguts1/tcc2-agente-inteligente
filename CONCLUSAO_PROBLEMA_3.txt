## ✨ Destaques Técnicos

### 1. Perfis Clinicamente Relevantes

```python
PERFIS_PREDEFINIDOS = {
    "baixo": {
        "limite_tempo_postura": 150,  # Mais tempo entre mudanças
        "prob_falha_reposicao": 0.4,  # Poucas falhas
    },
    "medio": {
        "limite_tempo_postura": 120,  # Normal
        "prob_falha_reposicao": 0.7,  # Falhas moderadas
    },
    "alto": {
        "limite_tempo_postura": 90,   # Pouco tempo
        "prob_falha_reposicao": 0.85, # Muitas falhas
    },
}
```

### 2. Três Modos de Operação

```python
# Modo 1: Uniforme (padrão)
gerar_sessao_multi(pacientes=10, ...)
# Todos com perfil 'medio'

# Modo 2: Heterogêneo automático
gerar_sessao_multi(pacientes=10, distribuir_por_risco=True, ...)
# Alterna: baixo, médio, alto, baixo, médio, alto, ...

# Modo 3: Customizado
gerar_sessao_multi(pacientes=2, perfis_customizados=[...], ...)
# Usa perfis específicos fornecidos
```

### 3. Sem Breaking Changes

## 🎓 Lições Aprendidas

1. **Perfis clinicamente relevantes importam:**
   - Não use valores aleatórios
   - Considere cenários reais de hospitais
   - Valide com especialistas

2. **Backward compatibility é crítico:**
   - Ninguém quer refatorar código que funciona
   - Use defaults para novos parâmetros
   - Documente breaking changes (se houver)

3. **Testes guiam design:**
   - Escreva testes primeiro (TDD-light)
   - Testes documentam comportamento esperado
   - Testes salvam horas de debugging

4. **Demos valem documentação:**
   - Uma demo funcional > 100 linhas de docs
   - Executável = prova de conceito
   - Fácil para outros usarem/entenderem
