## 🔴 PROBLEMAS ATUAIS (HTTP)

1. **Latência Alta** - 500-1500ms por evento
   - Handshake TCP + SSL a cada POST
   - Headers HTTP redundantes (~200 bytes)

2. **Sem Push Real-time**
   - Servidor não consegue enviar pro ESP32
   - Só recebe quando ESP32 faz request

3. **Retry Manual e Complexo**
   - Backoff exponencial implementado manualmente
   - Bloqueia thread durante espera

4. **Escalabilidade Limitada**
   - ~100 devices simultâneos
   - Overhead alto com muitos POSTs

---

## 🟢 VANTAGENS WEBSOCKET

1. **Ultra-Rápido** ⚡
   - Conexão persistente = sem handshake
   - Latência: 120ms vs 800ms

2. **Comunicação Bidirecional** 🔁
   - Servidor envia comando START/STOP direto
   - Sem polling necessário

3. **Economia de Banda** 📉
   - Frames menores (2 bytes overhead)
   - 43% menos dados transmitidos

4. **Melhor Escalabilidade** 📊
   - ~1000+ devices simultâneos
   - Menos conexões = menos overhead

5. **Servidor Pronto** ✅
   - ConnectionManager já existe em interface/api.py
   - FastAPI tem suporte nativo

## ✨ EXEMPLOS DE CÓDIGO

### ESP32 (Antes - HTTP)
```cpp
bool enviarEvento(const EventoReplay &evento) {
  g_http.begin(g_client, url);           // ← Handshake!
  g_http.addHeader("Content-Type",...);  // ← Headers!
  int status = g_http.POST(evento.payload);
  g_http.end();                           // ← Close!
  // ~800ms por evento
  return status >= 200 && status < 300;
}
```

### ESP32 (Depois - WebSocket)
```cpp
bool enviarEvento(const EventoReplay &evento) {
  webSocket.sendTXT(evento.payload);  // ← Direto!
  // ~120ms por evento
  // Conexão reutilizada
  return webSocket.isConnected();
}
```
